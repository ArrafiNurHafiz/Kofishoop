# 📋 Product Requirements Document (PRD)

## **Eterna** — AI-Powered Digital Afterlife & Inheritance Executor

---

## 1. Executive Summary

### 1.1 Product Vision
> *"Ketika kita tidak lagi ada, aset digital kita tetap terlindungi dan terdistribusi sesuai keinginan — tanpa birokrasi, tanpa notaris, tanpa kecurigaan."*

**Eterna** adalah AI Agent berbasis blockchain yang mengeksekusi wasiat digital secara otonom. Agent ini memantau "kehidupan" pemilik wallet melalui multi-layer trigger mechanism dan mendistribusikan aset ke beneficiary yang telah ditentukan — sepenuhnya tanpa intervensi manusia.

### 1.2 Problem Statement
| Problem | Current State | Impact |
|---------|-------------|--------|
| **$140B+ Bitcoin hilang** | Wallet owner meninggal tanpa menyampaikan private key | Aset digital tidak bisa diakses oleh keluarga |
| **Proses warisan tradisional lambat** | Notaris, pengadilan, birokrasi — bisa 6-24 bulan | Keluarga dalam kesulitan finansial menunggu |
| **Tidak ada trustless inheritance** | Harus percaya pihak ketiga (exchange, lawyer) | Risiko fraud, mismanagement, atau kebocoran data |
| **Crypto holder demographic muda** | Banyak holder usia 25-40 tidak punya estate planning | Risiko meningkat seiring adoption crypto |

### 5.2 Smart Contract Architecture

```solidity
// ============================================
// ETERNA CORE CONTRACTS
// ============================================

// 1. EternaWill.sol — Core will storage & execution
contract EternaWill {
    struct Will {
        address owner;
        bytes32 encryptedDataHash;     // IPFS hash of encrypted will
        uint256 inactivityThreshold;   // e.g., 180 days
        uint256 lastActivity;          // timestamp of last heartbeat
        address[] beneficiaries;
        uint256[] percentages;
        bool isExecuted;
        Guardian[] guardians;
    }
    
    struct Guardian {
        address guardianAddress;
        bool hasVoted;
        bool vote;
    }
    
    // Trigger mechanisms
    function checkIn() external;                    // Heartbeat
    function guardianVote(bool _isDeceased) external;
    function executeWill() external;                // AI Agent calls this
}

// 2. EternaGuardian.sol — Guardian management
contract EternaGuardian {
    function addGuardian(address _will, address _guardian) external;
    function removeGuardian(address _will, address _guardian) external;
    function getGuardianStatus(address _will) external view returns (uint256 votesFor, uint256 total);
}

// 3. EternaDistribution.sol — Asset distribution logic
contract EternaDistribution {
    function distributeAssets(
        address _will,
        address[] calldata _beneficiaries,
        uint256[] calldata _percentages
    ) external;
    
    function distributeWithConditions(
        address _will,
        Condition[] calldata _conditions
    ) external;
}
```

### 5.3 AI Agent Logic

```
┌─────────────────────────────────────────────────────────────────────┐
│                     AI AGENT: ETERNA ENGINE                         │
└─────────────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────────┐
  │  TRIGGER MONITOR (Runs every 24 hours)                          │
  ├─────────────────────────────────────────────────────────────────┤
  │  For each active will:                                          │
  │    1. Check lastHeartbeat vs inactivityThreshold                │
  │    2. Check guardian votes (if threshold met)                   │
  │    3. Check oracle confirmation (if configured)                 │
  │    4. Calculate confidence score:                               │
  │       confidence = (inactivityTrigger * 0.4) +                  │
  │                    (guardianConsensus * 0.4) +                  │
  │                    (oracleConfirmation * 0.2)                   │
  │    5. If confidence >= 0.7 → proceed to execution               │
  └─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │  EXECUTION VALIDATOR                                            │
  ├─────────────────────────────────────────────────────────────────┤
  │  • Verify will is not already executed                          │
  │  • Verify beneficiary addresses are valid                       │
  │  • Verify sufficient balance for distribution + gas             │
  │  • Verify no pending legal challenges (if oracle integrated)    │
  │  • Generate execution proof for audit trail                     │
  └─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │  DISTRIBUTION EXECUTOR                                          │
  ├─────────────────────────────────────────────────────────────────┤
  │  • Calculate exact amounts per beneficiary                      │
  │  • Execute transfers (batch if possible for gas efficiency)     │
  │  • Update will status to EXECUTED                               │
  │  • Emit events for notification service                         │
  └─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │  NOTIFICATION SERVICE                                           │
  ├─────────────────────────────────────────────────────────────────┤
  │  • Send email to each beneficiary with:                         │
  │    - Will summary                                               │
  │    - Amount received                                            │
  │    - Step-by-step claim guide                                   │
  │    - Support contact                                            │
  │  • Send on-chain message (if beneficiary has registered)        │
  │  • Update public execution log                                  │
  └─────────────────────────────────────────────────────────────────┘
```

## 9. Security & Privacy

### 9.1 Security Measures

| Layer | Measure | Implementation |
|-------|---------|----------------|
| **Data Encryption** | Will data encrypted before IPFS storage | AES-256 + owner public key |
| **Access Control** | Only owner can modify will | Smart contract ownership |
| **Execution Safety** | Multi-layer trigger prevents false execution | Confidence scoring (≥0.7) |
| **Guardian Integrity** | Guardians cannot collude easily | Minimum 3 guardians, threshold 2/3 |
| **Audit Trail** | All actions logged on-chain | ExecutionLog contract |
| **Emergency Stop** | Owner can pause/cancel will | Pause mechanism in contract |

### 9.2 Privacy Considerations

- Will content (beneficiary details, amounts) dienkripsi — hanya hash yang on-chain
- Beneficiary identity tidak terexpos sampai execution
- Guardian tidak tahu isi will, hanya bisa vote "deceased" atau not
